# ADR-0031 AI 判定ループは反証可能な「阻止」だけで閉じ、完成条件は終端ゲートの閉じたリストとする

## Context

ホスト案件で `/develop` の AI 判定ループ（structure-oracle ↔ contract-author、slice-reviewer ↔ implementer）が収束せず、開発が止まった。原因は 3 つあった。

1. 「矛盾ゼロ」に止まる基準がない。判定役の任務は「欠陥を暴く」ことで、重大度の語彙がなく、大きな穴がなくなると同じ注意をより細かい粒度に向ける。低 1 件でも「矛盾あり」として回り続けた。サーキットブレーカーは「同じ欠陥が 3 ラウンド生き残る」場合にしか発火せず、毎回別の低指摘が出る状態を止められなかった。
2. 手戻りの単位が「指摘」だった。producer に「最小限に直せ」と局所パッチを指示する一方、判定役は全体を読む。継ぎはぎと周囲のずれが次のラウンドの指摘になった。
3. 判定役が指摘できる範囲と、機械が検査できる範囲が分かれていなかった。判定役の指摘は散文で producer に戻され、機械検査に変換されないまま次のラウンドで再判定された。

ADR-0030 は意味の検証を独立した AI に任せると決めたが、その判定をどう閉じるかを定めていなかった。設計文書の原理を採る: 「欠陥 0」は緩めない。対象を「閉じていて、単調に減り、収束しなければ人間が見る」ものに限定する。アンチパターンは「欠陥 0」ではなく「閉じていない基準への 0 要求」である。

## Decision

- 判定役（`reviewer`）の指摘は 2 段の閉じた語彙を持つ。**`阻止`** は機械検査に変換できる具体的な反例を伴う指摘（test-author がクラスを宣言できる失敗テスト、spec-lint / trace-check / contract-run の規則、または REQ 文と違反入力）。**`持ち越し`** はそれ以外（表現の曖昧さ、重複、テストや例で白黒がつく境界、様式）。反例のない指摘は `阻止` になれない。収束は「`阻止` ゼロ」であり、`持ち越し` が残っていても clean である。
- `阻止` は producer に散文で戻さない。テストのクラスか lint 規則に変換して機械ループへ戻す。`持ち越し` は orchestrator が `docs/verification/DEFERRED.md`（書式は `templates/develop/DEFERRED.md`、spec-lint が検査）に記録し、同一スライスでは再送しない。解消か機械検査への昇格で行が消える（縮む方向にしか動かない）。
- 停止規則: reviewer は 1 スライスにつき最大 2 回（終端 + 再確認）。`阻止` 数が減らなければ、台帳・反例・診断（矛盾する REQ / BR 文、曖昧な検査）を添えて人間へ戻す。今ラウンドの再導出に起因する指摘は同一箇所として数える。非収束は診断であって、次のラウンドの理由ではない。
- 手戻りの単位は成果物（操作 / 文書 / ユニット）であって指摘ではない。producer は名指しされた単位を SSOT から再導出し、指摘ごとに `re-derived / already satisfied / needs SSOT change` を返す。orchestrator は「最小限に直せ」と言わない。
- 完成条件は終端ゲートの閉じたリストと一致させる: `spec-lint validate` 0、`trace-check` 新規違反 0、`contract-run` fail 0（アダプタ宣言時）、`traceconfig.json` `commands.*` exit 0、reviewer が `阻止` ゼロで閉じている、`持ち越し` が DEFERRED.md に記録済み、触った UC の `phase: 完了`。ホストが Claude Code の Stop hook に `tools/gate-hook/stop-gate.mjs` を明示設置すれば機械が強制する。設置しないホストでは orchestrator が終了前に同じリストを自分で実行する。
- 工程中のゲート（PreToolUse の `gate-hook`、着手ゲート）は残すが推奨に格下げする。両 hook は `.harness-gate/log.jsonl` に拒否ログを書き、`gate-log.mjs --summary` で「一定期間 block 0」を可視化する。降格の決定はこのデータから人間が行う。

強制の所在: `阻止` / `持ち越し` の語彙と停止規則は reviewer の出力契約と develop skill（説得的制御、R-901）。終端リストは stop-gate（構造的制御、ホスト opt-in）。DEFERRED.md の書式は spec-lint。

## Consequences

- 収束が定義可能になる。判定役の探索が細かくなっても、反例を伴わない指摘はループを回さない。
- `持ち越し` の蓄積とその triage は人間の責務として残る。DEFERRED.md の経過日数と再出現は spec-lint が warn するが、昇格するかどうかは人間が決める。
- 反例の要求により、judge が反例を書けない真の欠陥を `持ち越し` に落とす可能性がある。終端の人間ゲート（SSOT / UI / DB）と `/attack` は引き続き必要である。
- 成果物単位の再導出は局所パッチよりトークンを使う。往復回数の減少で相殺されるかは運用計測で確認する。
- Stop hook は終了ごとに git を呼ぶ。変更検出で無変更時は skip するが、スイートの長さはホストの責任である。ラウンド上限で解放された終了は未検証として人間が見る。

## 却下した選択肢

- **「矛盾ゼロ」を維持しブレーカーの閾値だけ下げる**: 同一欠陥の生存しか見ないため、新規の低指摘の連鎖を止められない。
- **重大度を 3 段以上にする**: 中と低の境目が判定役の裁量になり、反証可能性で決まらない。2 段なら境界は「反例を書けるか」の 1 点で決まる。
- **`持ち越し` も同一スライスで producer に直させる**: 局所パッチの連鎖が再発する。
- **Stop hook で毎回スイートを無条件実行する**: 対話ターンでも走り、コストで外される。変更検出とラウンド上限を持たせる。
- **保留を `.spec-baseline.json` / `.trace-baseline.json` に入れる**: baseline は既知の機械違反の台帳であり、判断を混ぜると「縮むだけ」の意味が壊れる。
- **工程ごとの Stop ゲートを置く**: 工程は `UC.md` の `phase` で読めるが、工程別に停止条件を書くと説得的制御に戻る。終端 1 箇所で成果物の性質だけを判定する。
