# ADR-0074 書く担当と判定する担当が、設定の rules・conventions・exceptions を読んで従う

## Context

ADR-0064 で、プロジェクトの決めごとを `harness.config.json` の `rules`（ほかに正本がある決めごと）・`conventions`（機械が確かめていない決めごと）・`exceptions`（人間が認めた例外）に集めた。ただし、それを読むのは `lint config` だけで、担当（agent）が読んで従う記述はパッケージに無かった。ADR-0064 は、この変更を含まないと書いていた。

`rules` の決めごとは、指した `commands` が確かめる。`conventions` は機械が確かめないので、担当が読まなければ誰も見ない。

## Decision

- コードとテストを書く担当（`implementer`、`test-author`）は、開始前に `harness.config.json`（monorepo では書くパスの unit のもの）の `rules`・`conventions`・`exceptions` を読み、書くものをそれに従わせる。`exceptions` が認めていない決めごとに従えないときは、矛盾を報告して停止する。設定は書き換えない（設定はオーケストレーターが書き、書き込みは人間の承認に回る。ADR-0057）。
- 判定する担当（`reviewer`）は、成果物が `conventions` に反し、`exceptions` も認めていなければ、決めごとの文と違反の位置を反例として `阻止` にする。`rules` が指す決めごとは機械が確かめるので、読み直さない。
- 仕様を書く担当（`spec-author`）と攻撃する担当（`attacker`）には足さない。仕様の書き方はテンプレートと文書の規約が決め、攻撃は決めごとではなく稼働している環境を相手にする。
- 強制の所在: 担当の定義（入力契約と不変条件）に書く。担当が読んだかは機械で確かめていない（説明文による統制。R-901）。

## Consequences

**得られるもの**

- 機械が確かめていない決めごとを、書く担当が読み、判定する担当が違反を指摘する。利用プロジェクトは決めごとを `CLAUDE.md` に書き直さなくてよい。
- `exceptions` に書いた例外が、担当の判断に効くようになる。検査の違反を免除しないこと（ADR-0056）は変わらない。

**代償と今後の制約**

- `阻止` の反例に、機械検査にできない「決めごとの文と違反の位置」が加わる。`conventions` の決めごとが曖昧だと、判定がぶれる。決めごとを機械で確かめられるようになったら、`rules` へ移す（ADR-0064）。
- 利用プロジェクトの `CLAUDE.md` に残る決めごとは、設定へ移すまで担当がどちらも読む。食い違えば、担当は矛盾として報告する。

## 却下した選択肢

- **オーケストレーターが決めごとを要約して担当に渡す**: 要約で決めごとの文が変わり、正本が 2 つになる。担当が設定を直接読む。
- **すべての担当に足す**: 仕様を書く担当と攻撃する担当には、従う対象の決めごとが無い。読む指示だけが増える。
- **`conventions` の違反を `問い` にする**: 決めごとは人間が既に決めており、答えは決まっている。人間に聞き直すことではない。
