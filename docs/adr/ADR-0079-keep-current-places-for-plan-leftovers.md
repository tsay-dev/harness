# ADR-0079 2026-11-17 の計画の残りの 6 案は仕組みを足さずに見送り、今ある置き場と検査で扱う

## Context

2026-11-17 の計画は、「機械が読む仕様 1 枚」を前提に、仕様の量の上限を違反にする、仕様から人が読む面を作る道具（`render`）を足す、スライスの状態（phase）に「人間待ち」「取り下げ」を足す、UC に「決めたこと（捨てた案）」「意図して決めていないこと」の欄を置く、完了を機械の検査だけで判定する、`rules-crow` にも lint で止める項目の一覧（ADR-0075）を作る、という案を含んでいた。前提の「機械が読む仕様 1 枚」は 2026-11-18 にやめた。

依頼主は 2026-11-19 に、残りの 6 案の扱いを決めた。どれも「新しい仕組みを足さず、今ある置き場で扱う」という同じ判断なので、1 つの記録にまとめる。

## Decision

1. **仕様の量の上限は警告のままにする。** lint spec の UC・REQ・BR の本文の文字数、EARS の 1 文の長さ、契約の行数の上限（`tools/lint-spec/lint-spec.mjs` の `MAX_*`）は、超えても失敗にしない。
2. **`render` は作らない。** 仕様と検査の対応を人が見るときは `harness index` の索引を使う。
3. **phase に「人間待ち」「取り下げ」を足さない。** phase の語彙（定義・構造・実装・検証・完了）は lint spec が閉じたまま。人間待ちは、関門（guard の ask）と人間ゲートが人に回す仕組みで表す。取り下げは UC の撤回（`withdrawn`。ADR-0069）で表す。
4. **UC に「決めたこと（捨てた案）」「意図して決めていないこと」の欄を置かない。** 決めたことと捨てた案は ADR に書く。決めていないことは、プロジェクトの外の課題の管理の道具に書く。同じ事実を 2 か所に書かない。UC のひな形（`templates/develop/UC.md`）の節は変えない。
5. **完了の条件は ADR-0068 のまま。** 判定の担当（reviewer）の止める指摘（`阻止`）がゼロで、人に聞いた問いにすべて答えが出たら完了。reviewer はスライスごとに最大 2 回（develop skill）。機械の検査だけで完了にはしない。
6. **`rules-crow` の lint で止める項目の一覧は、いまは作らない。** crow の案件を次に触るときに作る。ADR-0075 の「`rules-crow` には、まだ適用していない」は今もそのまま正しいので、ADR-0075 は書き換えない（R-802）。

強制の所在: 1 と 3 は lint spec（警告の扱いと phase の閉じた語彙）、5 は develop skill の完了の定義と判定の担当の契約。2・4・6 は何も足さないという判断で、強制する仕組みは無い。

## Consequences

**得られるもの**

- 道具、状態、欄、文書の置き場が増えない。同じ事実の置き場が 1 つのまま保たれる。
- 完了の判定に、人が答える問いが残る。機械の検査が見ない意味の誤りを、判定の担当と人が止める。

**代償と今後の制約**

- 量の上限を超えた UC や契約は警告だけで残る。警告を読まない agent は、仕様を膨らませ続けられる。
- 人が読む面は索引と各文書だけで、UC と REQ と契約を 1 つの読み物として通しで読む手段は無い。
- 「意図して決めていないこと」が UC から見えない。UC を読む agent は、課題の管理の道具を見なければ、決めていないのか書き忘れたのかを区別できない。
- `rules-crow` の lint で止められる決まりは、一覧を作るまで文章のまま散っている。

## 却下した選択肢

- **量の上限を違反にする**: 上限の値は目安で、超える正当な UC もある。違反にすると、上限を通すために UC を機械的に割る動機が生まれる。
- **`render` を作る**: 前提の「機械が読む仕様 1 枚」をやめたので、人が読む面を別に作る理由が無い。対応の表示は `harness index` が既に持つ。
- **phase に「人間待ち」「取り下げ」を足す**: 状態が 2 か所（phase と関門・status）に分かれ、食い違ったときにどちらが正しいかが決まらない。
- **UC に決めたこと・決めていないことの欄を置く**: ADR と課題の管理に同じ事実を写すことになり、片方だけ直すと食い違う。
- **機械の検査だけで完了にする（2026-11-17 の計画）**: 仕様が答えを決めていない点や意味の誤りは機械の検査では見つからない。ADR-0068 で人に聞くことにした問いが、完了の前に答えられないまま残る。
- **`rules-crow` の一覧をいま作る**: 触る予定の案件が無く、作っても実際の lint の設定で確かめられない。
- **ADR-0075 の rules-crow の行を「いまは作らない」に書き換える**: accepted の ADR は書き換えない（R-802）。その行は今も事実なので、置き換えの ADR も要らない。
