# ADR-0039 ブランチ名とコミットメッセージの書式は git-lint が検査し、ホストは traceconfig.json の git で宣言する

## Context

これまでプロジェクトごとにリポジトリを分けていたが、モノレポで管理するプロジェクトが出てきた。モノレポでは「本線は 1 本」「アプリごとの本線を作らない」「ブランチ名はアプリ名で始める」という運用を、エージェントが毎回同じように行う必要がある。

`commit.md` には「既定ブランチに直接コミットしない」としか書かれておらず、どこから切るか・どう名付けるかは決まっていなかった。また、コミットメッセージの書式（Conventional Commits）とブランチ名には機械検査が無く、守られるかどうかは orchestrator が文章を読んで従うことだけに依存していた。既存の機械検査（`spec-lint gate`、gate-hook、stop-gate、CI の spec-gate）はどれもブランチ名を見ない。

「手順を足す前に機械検査を足す」がこの harness の方針であり、文章だけの規則は説得的な統制にとどまる（R-901）。

## Decision

- ブランチの基点・寿命・命名は orchestrator の手順として `commit.md` の「Cutting the branch」に置く。
- そのうち判断を要さない部分を `tools/git-lint` が検査する。
  - ブランチ名: `<接頭辞>/<topic>` の形、接頭辞が宣言された unit か `repo`（モノレポ）またはコミットの `type`（単一ユニット）、`topic` が小文字 ASCII のケバブケース 2〜5 語。
  - コミットメッセージの 1 行目: `<type>(<scope>): <subject>` の形、`type` の閉じた語彙、末尾の句点なし、モノレポでは `scope` が必須で unit か `repo`。
- ホストは `traceconfig.json` の `git` ブロックで宣言する。`git.units` がモノレポのユニット（名前とディレクトリ）の唯一の宣言場所で、orchestrator もここから読む。`git` が無いホストでは検査は実行されず、「検査していない」と出力する（pass とは扱わない）。`git.exempt_branches` は bot のブランチを対象外にする。
- 強制の所在は CI である。再利用ワークフロー `.github/workflows/spec-gate.yml` が PR ごとにブランチ名と各コミットを検査する。merge を止めるのは、ホストが既定ブランチの保護でそのジョブを必須チェックにしたときである。
- orchestrator はブランチを切った直後に同じツールで名前を確かめる。ローカルの commit-msg / pre-push フックは任意とする。
- `type` の語彙は `commit.md` の表とツールの両方にあり、ツールのテストが一致を固定する。

「どの unit を選ぶべきだったか」「既定ブランチから切ったか」「1 スライス 1 ブランチか」は機械では決まらず、`commit.md` の文章による説得的な統制のままである。

## Consequences

- モノレポでも単一リポジトリでも、宣言したホストではブランチ名とコミットの書式が PR で機械的に決まる。スタブを置いているホストは、`git` を宣言するだけで有効になる。
- 既存ホストは `git` を宣言するまで挙動が変わらない。
- CI は事後検査である。ブランチ名の誤りが PR で見つかると、直すにはブランチと PR を作り直すことになる。orchestrator が切った直後に確かめることで減らせるが、無くせはしない。
- ブランチ保護を設定しないホストでは、検査は失敗を表示するだけで merge は止まらない。この設定は harness からは入れられない。
- モノレポでは `scope` が unit 名に限られ、`auth` のような機能領域を `scope` に書けなくなる。
- `type` の語彙が 2 か所に存在する。テストが一致を固定するが、片方だけを直すとテストが落ちるまで気づかない。
- squash merge を使うホストでは、main に残るのは PR タイトルであり、これは検査していない。

## 却下した選択肢

- **git の規則を instruction leaf（rules）として配る**: leaf は producer が書くファイルのアドレスに `applyTo` で届く。git 操作にはアドレスが無く、git を実行する orchestrator は leaf を受け取らない。`applyTo: "**"` にすれば届くが、実質は常駐ルールになる。
- **ユニットをホストの `CLAUDE.md` / `AGENTS.md` に表で宣言する**: 機械が読めず、検査のために同じ事実を別の場所へもう一度書くことになる。
- **差分とブランチ名の整合を検査する**（`app-a/…` なら `apps/a/` に変更がある、`repo/…` ならどのユニットにも触れない）: リポジトリ全体の依存更新や、docs だけの変更で正しい名前が落ちる。判断を機械に持たせることになる。
- **宣言なしで常に検査する**: タグを上げた既存ホストの PR と bot のブランチが、何も設定していないのに落ちる。
- **gate-hook やローカルフックを強制の所在にする**: クローンごと・個人ごとの設定で、`--no-verify` で回避できる。任意の早期検査としては残す。
- **git-lint 用に別の再利用ワークフローを作る**: ホストがスタブをもう 1 つ置く必要がある。既存のスタブにステップを足せば追加設定が要らない。
- **spec-lint にサブコマンドとして足す**: spec-lint は docs の書式とライフサイクルの検査であり、git の名前の検査を混ぜると責務が広がる。
- **PR タイトルも検査する**: タイトルの編集は既定の `pull_request` イベントでは再実行されず、再実行しても古いタイトルが渡る。ホストのスタブに `edited` を足す必要があり、今回の範囲では採らない。
