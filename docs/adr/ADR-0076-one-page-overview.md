# ADR-0076 ビジョン・アクター表・GOAL・バックログを 1 枚の概要にまとめ、並行性と外部依存の共通の決めごとを全体の方針として書く

## Context

利用プロジェクトの「なぜ作るか」と「誰のための何か」は、`00-vision.md`（課題・対象ユーザー・KPI・やらないこと）、`02-actors.md`（アクターの表）、`goals-backlog.md`（未着手の GOAL）、ゴールごとの `GOAL.md`（目指す状態の 1 文と actor・origin・status）の 4 種類に分かれていた。全 agent が毎回これらを開き、「誰が」の記述は vision の対象ユーザーとアクターの表の 2 か所にあった。GOAL の ID は、着手済みならフォルダの `GOAL.md`、未着手ならバックログの `###` 見出しで定義していたので、着手のたびに定義の場所が移り、ID の重複の検査（lint refs C12）はバックログの ID を見落としていた。

また、UC の例外系の走査（R-502）は、並行性と外部依存の行を UC ごとに書かせていた。同じ対象に要求が重なったときにどちらを通すか、外部の情報が古いかもしれないときに何を前提にするか、外部が応答しないときに何を残すか、という決めごとはプロジェクトに共通のことが多く、UC ごとに同じ文が写されていた。

## Decision

1. **1 枚の概要 `docs/00-overview.md`（id `OVERVIEW`、status `draft | living`）に、課題・成功の定義（KPI の表）・アクター（対象ユーザーの散文と閉じた表）・GOAL の表・全体の方針・やらないことを置く。** 用語集（`01-glossary.md`）は別のファイルのまま残す。節・表の列（必須の列と、`<!-- 任意の列: ドメイン -->` で示す任意の列）・方針の見出しは、ひな形 `templates/develop/00-overview.md` から導く。読み方は `tools/_shared/overview.mjs` の 1 か所に置き、lint spec・lint refs・guard・next-id・index・migrate overview が使う（REQ の読み方を共有した ADR-0067 と同じ型）。
2. **GOAL の ID は、概要の GOAL の表の行で定義する。** 列は `ID | 目指す状態 | アクター | KPI | status | 備考`。行の status は `planned`（未着手）| `draft` | `active` | `withdrawn` の閉じた語彙。未着手も撤回済みも同じ表に置く。GOAL のフォルダ `docs/goals/GOAL-nn-<slug>/` は `planned` でない行の GOAL にだけ置け、フォルダがあれば行が要る（lint spec と C9）。`GOAL.md` は置かない。
3. **`00-vision.md`・`02-actors.md`・`goals-backlog.md`・`GOAL.md` は廃止した文書で、残っていれば違反にする。** 名前を変えて残したものも、frontmatter の id（`VISION`・`ACTORS`・`GOALS_BACKLOG`・`GOAL-nn`）で見つける。設定のキー `docs.vision`・`docs.actors`・`docs.goals_backlog` も廃止し、`docs.overview` に替える（K6 と lint refs の設定エラー）。案内はどちらも `harness migrate overview`。
4. **概要の置き場は 1 つに固定する。** `docs.overview` に書けるのは `<docs>/00-overview.md`（docs は `--docs` のフォルダか `docs.goals_dir` の親）か理由付きの none だけで、ほかのパスは設定の誤り。lint spec・lint refs・guard が別のファイルを読まないようにするため。GOAL のフォルダがあるのに none なら C9 と C26 が違反にする。
5. **全体の方針は `## 全体の方針` の 3 つの小節（`### 同時に届いた要求`・`### 外部の情報の遅れ`・`### 外部が応答しない`）に 1 段落ずつ書く。** 見出しは閉じた語彙で、ひな形から導く。方針は任意で、未記入の間は小節の本文を「（未記入: …）」の 1 行のまま残す。3 つの小節がすべて埋まり、概要が `living` のときだけ、UC は例外系の走査の並行性・外部依存の行を省ける（省いた行は方針どおりと読む）。方針と違う振る舞いにする UC は、導出の欄に「方針の例外（`見出し`）: …。理由: …」と REQ を書き、lint spec が見出し・理由・REQ を検査する。権限・不変条件違反の行は今までどおり必須。
6. **人のゲート（guard）。** 概要への書き込みで、GOAL の表から行が消える（status によらず）か、active の行が active でなくなるなら降格として承認に回す。全体の方針の小節の本文が変わる書き込みも、概要の status によらず承認に回す。行が active になるのは、これまでの `GOAL.md` と同じく記録して通す（GOAL の active は実装の着手を開けないので、人に回さない）。
7. **移行は `harness migrate overview` が行う。** 4 種類を読み、ひな形の案内だけを落として意味を変えずに概要を組み立て、検査と同じ読み方で読み戻して一致を確かめてから書く。定形の外の行、案内でない HTML コメント、vision とアクター表の status の食い違いがあれば何も書かずに失敗する。概要の status は vision とアクター表の status から決める（`frozen`・`living` → `living`）。設定は書き換えず、`docs.overview` の案を表示する（設定の変更は人のゲート。ADR-0057）。

## Consequences

- 全 agent が読む文書が 1 枚になり、「誰が」の記述が 1 か所になる。GOAL の ID の定義が 1 か所になり、C12 と next-id は `planned`・`withdrawn` の行と、行の無いフォルダの番号も数える。
- **方針どおりとして行を省いた UC の並行性・外部依存は、機械で確かめられなくなる。** 省いた行には REQ もテストも生まれず、方針の段落の正しさは人の承認と reviewer の確認（説得による統制）だけに頼る。方針の段落から `→ BR-nnn` を書いて C4・C16・C22 の経路でテストを求める案は、決まりを増やさないために今回は入れず、依頼主が後で決める点として残す。
- **方針の書き換えは、行を省いたすべての UC の意味を一度に変える。** guard が承認に回すが、承認する人が影響を受ける UC を自分で辿る必要がある。
- **方針どおりの書き方が 2 通り残る。** 行を書かない書き方と、「なし: 」に続けて方針を言い換えると書く書き方の両方が通る（今ある UC は 4 行とも書いてあるので、そのまま通る）。方針を埋めるときに、言い換えの行を外すかをプロジェクトが決める。
- 概要は R-1005 の行数の目安（おおむね 100 行）を超えやすい。扱いはこれまでの vision と同じで、機械では止めない。
- 利用プロジェクトは `harness migrate overview --write` で移し、設定の `docs` を直し、古い名前を書いている箇所（docs、`CLAUDE.md`・`AGENTS.md`）を手で直す必要がある。ADR は過去の記録なのでそのまま残す。

## 却下した選択肢

- **未着手を別の表（またはバックログの節）に残す**: 着手のたびに行を表から表へ移すことになり、ID の定義が 2 か所に分かれる。C12 がバックログの ID を見落としていたのも、この分かれ方が原因だった。
- **「着手済みか」の列を持つ**: status とフォルダの有無から決まる事実を、3 か所目に書くことになる。
- **`GOAL.md` を薄くして残し、概要から読み込む表示を作る**: 正本と表示の 2 つを持つことになる（ADR-0067 で却下した案と同じ理由）。
- **用語集も概要に入れる**: 量が多く、全 agent が毎回読む概要が長くなる。C25 の読み方も別。
- **GOAL の ID をフォルダの名前だけで定義する**: 未着手と撤回済みの GOAL はフォルダを持てない。
- **UC に「目的」の欄を足す**: GOAL の文を UC ごとに写すことになる。UC だけの理由は「概要」の 1 文で足りる。
- **「方針どおり」と書く行を必須にする**: 書く量が減らず、省くために方針を置く意味が無くなる。
- **方針の例外に REQ を求めない**: 代わりの振る舞いが観測できるのに、テストの義務が無くなる（R-104）。
- **全 UC の例外系を書き直させる**: 意味が同じかを機械で確かめられず、すべての UC で人の確認が要る。
- **方針の段落に `→ BR-nnn` を書けるようにし、C4・C16 で数える**: 方針の検証をテストへつなげられるが、決まりが 1 つ増える。今回は見送り、上の代償として残す。
- **方針が living なら 3 つの小節を必須にする**: 移行で概要を draft に落とすと、承認済みの vision・アクター表・GOAL を降格させることになる。方針は任意にし、埋まるまで行を省けないことで扱う。
- **migrate が設定も書き換える**: 設定の変更は人のゲートで、JSON を書き直すと長い `_comment` の並びも崩れる。
- **`docs.overview` に任意のパスを書けるようにする**: lint spec は `<docs>/00-overview.md` を決め打ちで読み、refs と guard は設定を読むので、食い違うと別のファイルを検査することになる。
- **GOAL の active への昇格を guard で人に回す**: 実装の着手を開けない変更で、今の `GOAL.md` の扱いより厳しくなる。
