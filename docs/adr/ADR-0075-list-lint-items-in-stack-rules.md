# ADR-0075 lint で止められる決まりは、スタックの規約に「止める項目の一覧」として 1 か所だけ持つ

## Context

スタックの規約（`rules-*`）には、`any` の禁止、default export の禁止、機能をまたぐ読み込みの禁止のように、lint で機械的に止められる決まりが、文章として複数の文書に散っていた。文章の決まりは、AI が見落としても誰も気付かない。利用プロジェクトが lint の規則を書いても、規約の文章と lint の設定の 2 か所に同じ決まりが残る。

テストが本番のコードを、テストの入口を通らずに直接読み込まないことも、ADR-0066 と `harness lint entry` の README で「プロジェクトの lint で止める」と書いただけで、規約の項目にはなっていなかった。

依頼主は 2026-11-17 に、lint で止められる決まりは harness が「止めるべき項目の一覧」だけを持ち、lint の設定はプロジェクトが書くことを了承した。harness は仕様と実装を紐づける仕組みであり、特定の lint の道具や規則の書き方に寄せない。

## Decision

- スタックの規約のパッケージは、lint（型検査を含む）で止められる決まりを、1 つの文書（`common-lint`）に「止めること」と「対象」の表として持つ。ほかの文書は、その決まりを文章で繰り返さず、一覧を指す。
- 一覧は、使う道具、規則の名前、設定の書き方を書かない。止め方は利用プロジェクトが決め、`harness.config.json` の `rules` から設定のファイルと確かめるコマンドを指す（ADR-0064）。まだ止めていない項目は、止めるまで `conventions` に書く。
- 仕様のテスト（`@covers` を持つテスト）が、テストの入口・テストの足場・共有の契約スキーマ以外の本番コードを読み込まないことを、一覧の 1 項目にする。
- lint では見分けられない決まり（ミドルウェアが応答を返すか、ロケーターが偶然の画面文言から来ていないか）は、文章のまま残す。
- 一覧は、本文から決まりを移した元の規約と同じアドレス（本番のコードとテスト）に加えて、lint の設定のファイルと `harness.config.json` を書くときに届く（`applyTo`）。コードを書く担当には、決まりが一覧として届く。
- `rules-cloudflare-hono-react` と `rules-righthub` は共通の規約を `rules-hono-react-spa` から引き込む（ADR-0072）ので、一覧もそこに 1 つだけ置く。`rules-next`・`rules-expo`・`rules-swiftui` は、それぞれのパッケージに 1 つ置く。
- 強制の所在: 一覧の項目を止めるのは利用プロジェクトの lint であり、harness は確かめない。止めていない項目は、`conventions` の一覧として `harness lint config` が毎回表示する。`conventions` を書く担当が読み、判定する担当が違反を指摘する（ADR-0074）。

## Consequences

**得られるもの**

- lint で止められる決まりが 1 か所に並び、利用プロジェクトは一覧を見て lint の規則を書ける。規約の文章と lint の設定の二重化が無くなる。
- 止めていない項目が `conventions` に並ぶので、機械が見ていない範囲が見える。
- テストが本番のコードを直接読み込むことを止める項目が、規約の中に場所を持つ。

**代償と今後の制約**

- 一覧の決まりは、コードを書く担当に届くが、機械で止めるのは利用プロジェクトの lint だけ。利用プロジェクトが lint で止めず、`conventions` にも書かなければ、判定の担当は見ない（書く担当が一覧を読んで従うだけになる）。
- `rules-cloudflare-hono-react` と `rules-righthub` の `backend-testing` は、純粋な業務関数と service を直接テストする行を持つ。仕様のテストを入口からだけ呼ぶ項目と両立させるには、その行が仕様のテストでないこと（技術部品の自己検査として `tests.dirs` の外に置く）を決める必要がある。この変更では決めていない。
- `rules-crow` には、まだ適用していない。同じ形で一覧を作るまで、決まりは文章のまま散っている。
- `rules-swiftui` の仕様のテストは、入口の表が示す UseCase を直接構築する。読み込みの単位（モジュール）では入口とそれ以外を分けられないので、テストが入口から入ることは一覧の項目にしていない。

## 却下した選択肢

- **harness が lint の設定（ESLint の規則など）を配る**: 特定の道具に寄せることになり、道具を替えたプロジェクトに使えない。仕様と実装の紐づきに関係しない。
- **決まりを文章のまま残し、lint でも止める**: 規約の文章と lint の設定の 2 か所に同じ決まりが残り、片方だけ直すと食い違う。
- **一覧を `harness.config.json` のひな形に書く**: スタックによって止める項目が違う。スタックの事実は、選んだスタックの規約が持つ。
