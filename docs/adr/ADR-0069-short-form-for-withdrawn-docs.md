# ADR-0069 撤回済みの文書は短い形にし、効いていた頃の節を検査で求めない

## Context

仕様の ID は消さず、廃止は `status: withdrawn` で表す（R-201）。spec-lint は、撤回済みの文書も「確定した文書」として扱い、必須の節とその中身を求めていた。

- 撤回済みの REQ にも「検証方針」の見出しを、撤回済みの UC にも状態 × イベント表のデータ行と例外系の 4 分類の行を求めた。
- 利用プロジェクトの 1 つには、撤回済みの REQ が 110 件、UC が 3 件あり、効いていた頃の全文（約 25 万字）がそのまま残っていた。文書を全部読んで作業する担当の負担になり、もう効かない決まりを今の決まりと取り違える元にもなっていた。
- 縮めようとしても、検査が落ちるので、空の「検証方針」の見出しや「なし: 撤回済み」とだけ書いた表を残すしかなかった。
- 参照の無い撤回済みの BR は、trace-check の C4（死んだ規則）で落ちた。active な文書から参照すれば C16 が落とすので、撤回済みの BR を置ける場所が実質無かった。

## Decision

- 撤回済みの文書は、短い形にする: frontmatter（必須の項目は全部）、題、撤回の理由、そして REQ・NFR・GOAL は元の要件文の 1 文。効いていた頃の節は残さない。経緯は git と ADR が持つ。
- 撤回の理由は、REQ は項目 `- note:` に、ほかは本文の 1 文に書く。決定の記録があれば番号を添える。
- spec-lint は、`status: withdrawn` の UC・REQ・BR・NFR に、必須の節の存在と中身、UC の表の中身、BR の「意図」、NFR の測定方法を求めない。frontmatter、ID と置き場の一致、ひな形の穴埋めの残り、REQ・NFR の要件文は、これまでどおり検査する。
- 撤回済みの REQ に `- note:` が無ければ、spec-lint が warn を出す。
- trace-check の C4 は、撤回済みの BR を対象から外す。
- 強制の所在: `tools/spec-lint/test/spec-lint.test.mjs` が、撤回済みの短い形が通ること、撤回済みでなければ節の欠落が err のままであること、撤回済みでも要件文が要ることを確かめる。

## Consequences

**得られるもの**

- 撤回した決まりが、今の決まりと同じ重さで文書に並ばなくなる。読む量が減る。
- 撤回の理由が、決まった場所に 1 文で残る。

**代償と今後の制約**

- `status` を `withdrawn` にすると、その文書の節の検査が外れる。active からの降格は、書き込み前の関門（gate-hook）が人間の承認に回す（ADR-0057）。関門を有効にしていないプロジェクトでは、降格を止める仕組みが無い。
- 撤回済みの仕様を指す注釈・表・契約は、trace-check が違反にする（ADR-0056）ので、撤回してもテストや実装が残っていれば検査が落ちる。義務を消すために撤回することはできない。
- 効いていた頃の文面は、文書からは読めなくなる。必要なときは git の履歴を見る。履歴が浅い複製では辿れない。
- 撤回の理由が書かれているかは、REQ の `note` の有無しか機械で見ていない。UC・BR・NFR の理由の文と、理由の中身が妥当かは、人が見る。
- 既にある撤回済みの文書は、自動では縮まらない。利用プロジェクトが縮める。

## 却下した選択肢

- **撤回済みの文書を消す**: ID が再利用されうる。過去のコミットやレビューの記録が指す ID が、何だったのか分からなくなる。
- **撤回済みの文書を別のフォルダへ移す**: ID の置き場が 2 つになり、検査と索引がどちらも読む必要が出る。
- **今のまま、全文を残す**: 読む量と取り違えの元が残る。
