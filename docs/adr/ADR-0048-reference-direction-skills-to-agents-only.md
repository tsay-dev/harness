# ADR-0048 参照は skills → agents の 1 本だけにし、agents は規約を名指しせず、rules は skill と agent を知らない

## Context

削減後も参照は 3 方向に残っていた。agent 本文は読むべき規約をファイル名で名指しし（11 箇所）、rules の葉は develop skill の完了条件や「全件実行は完了条件と CI だけ」などの工程を知り（12 箇所）、`test-author` / `implementer` の名前と担当者表を持っていた（8 葉）。agent が規約を名指しすると、規約が増えるたびに agent 本文を直す必要がある。rules が agent の分解を知ると、agent を再編するたびに全スタックの葉を直す必要がある。ADR-0033 の 16 体 → 5 体の統合で旧 agent 名が葉に約 1 か月残ったのはこの結合の実害である。

規約がどの agent に届くかは、葉の `applyTo` と agent が書くパスの一致で機械的に決まる。Claude では生成した葉の `paths:` が自動で読み込み、ほかのプロバイダーではオーケストレーターが `references/bundles.md` に従ってパスを渡す。どちらでも agent 本文に規約名は要らない。

## Decision

- 参照は **skills → agents** の 1 本だけにする。オーケストレーターは起動する agent の名前、mode、tier を知る。
- **agents は規約を名指ししない。** 本文は「書くパスに対応する規約が届く。開始前に読み、届いた規約の対応表から導出する」とだけ書く。配送は Claude では `paths:`、ほかは bundles.md の経路で行い、agent はその方法を知らない。
- **rules は skill と agent を知らない。** 葉は「そのパスに置くファイルの事実」だけを持つ。develop、完了条件、終端ゲート、全件実行の時点、agent 名、担当者表を書かない。担当の分割は「どのパスに何を置くか」で表し、作成者間の独立は「テストを書く側と実装を書く側は互いの成果物から導出しない」と一般名詞で書く。
- 全件実行の時点は散文で持たない。stop-gate と CI が機械で強制する。

強制の所在: `tools/apm/test_projection.py` が、agent 本文に `.instructions.md` と「末端ファイル」が現れないこと、`rules-*` の葉に `develop`、`完了条件`、`終端`、develop の 5 つの agent 名が現れないことを検査する。

## Consequences

- 良: 規約の追加や agent の再編が、相手側の本文の変更を要求しなくなる。
- 良: 葉はスタックの事実だけになり、プロセスの変更で葉を直す必要がなくなる。
- 悪: agent は規約の名前を知らないため、規約が届かなかったことに気づけない。Claude では `paths:` が担保し、ほかのプロバイダーではオーケストレーターの渡し忘れが沈黙する。bundles.md の「何も一致しなければ選択したスタックの葉をすべて渡す」を既定として残す。
- 悪: 検査は語の出現を見るだけで、言い換えた参照は止められない。

## 却下した選択肢

- **agents → rules の名指しを残す**: 規約の追加ごとに agent 本文が変わり、配送の仕組みを本文が重複して持つ。
- **rules → skills の参照を「完了条件」程度なら許す**: 工程の変更が葉に波及する。全件実行の時点は機械が強制しており、葉に書く必要がない。
- **rules に担当者表を残して agent 名だけ一般化する**: 「誰が書くか」は bundles.md の `applyTo` 照合で決まるため、葉に持つ情報ではない。配置の境界として書き直す。
