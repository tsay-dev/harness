# migrate overview

ビジョン（`00-vision.md`）・アクター表（`02-actors.md`）・バックログ（`goals-backlog.md`）・各ゴールの `GOAL.md` を、1 枚の概要（`docs/00-overview.md`）へ移す（ADR-0076）。入口からは `harness migrate overview`。

```
harness migrate overview [--root <プロジェクトのルート>] [--docs docs] [--write]
```

- `--write` が無ければ、何を移すかと、手で直す箇所と、設定の変更の案を表示するだけで、何も書き換えない。
- monorepo では unit ごとに `--root <unit のディレクトリ>` で実行する。
- 終了コード: 0 = 移せる（`--write` なら移した。移すものが無いときも 0）／1 = 移せないものがある（何も書かない）／2 = 使い方の誤り。

## 移し方

| 元 | 概要の置き場 |
| --- | --- |
| vision の「解決する課題」「やらないこと」 | 同じ名前の節 |
| vision の「対象ユーザー」 | アクターの節の、表の前 |
| vision の「成功の定義」の表 | KPI の表。先頭のセル `KPI-nn <指標>` を、ID と指標の 2 列に分ける。表の前後の文も残す |
| vision のひな形に無い節（`## 背景` など） | 概要の末尾に、元の順で |
| アクター表 | アクターの表（行はそのまま）。表の前後の文も残す |
| `GOAL.md` | GOAL の表の行。`>` の 1 段落が目指す状態。status の後ろに書いた文と、撤回の理由の 1 段落は備考 |
| バックログの `### GOAL-nn` の塊 | GOAL の表の `planned`（撤回済みなら `withdrawn`）の行 |

落とすのは、ひな形の案内（案内の HTML コメント、vision の末尾の 2 行、アクター表の末尾の 2 行、status の値の後ろの案内の文面）だけ。全体の方針は、ひな形の見出しと「（未記入: …）」を置く。概要の status は、vision とアクター表の status から決める（`frozen`・`living` → `living`、`draft` → `draft`）。

読む場所は、設定に古いキー（`docs.vision`・`docs.actors`・`docs.goals_backlog`）がパスで残っていればそのパス、無ければ docs のフォルダの既定の名前。組み立てた概要は、検査ツールと同じ読み方（`tools/_shared/overview.mjs`）で読み戻し、元の ID・status・アクター・KPI・目指す状態・備考と、KPI とアクターの表の全セルが一致することを確かめてから書く。

## 移せないもの（何も書かずに失敗する）

- `GOAL.md` に、案内でない HTML コメントがある。目指す状態の段落が 1 つでない。目指す状態のほかに段落がある（撤回済みの理由の 1 段落を除く）。
- バックログの塊に、定形（`- **actor**`・`- **由来**`・`- **ドメイン**`・`- **status**` と `>` の文）の外の行がある。塊より前に、案内でない行がある。バックログの ID と同じ ID のフォルダがある。
- vision の最初の `##` より前に本文がある。成功の定義の行の先頭が `KPI-nn` でない。アクター表に「アクター一覧」のほかの節がある。
- vision とアクター表の status が食い違う（降格も昇格もさせない。人が直してから移す）。
- `00-overview.md` がすでにある。

止まった箇所は、元の文書を直してから実行し直す（定形の外の文は、移した後に備考へ入れるか、UC・ADR・issue へ移す）。

## 移した後に人がすること

- 表示された設定の変更の案（`docs.overview` を足し、廃止したキーを消す）を、人間の承認で `harness.config.json` に入れる（設定は書き換えない。ADR-0057）。`docs.overview` に書けるのは `<docs>/00-overview.md` か理由付きの none だけ。
- 表示された「古い文書の名前を書いている箇所」を直す（ADR は過去の記録なのでそのまま）。
- 全体の方針の 3 つの小節を書き、人間が承認する（埋まるまでは、UC の並行性・外部依存の行を省けない）。
