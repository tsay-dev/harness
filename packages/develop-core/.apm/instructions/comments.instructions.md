# 💬 コード内コメントには現在の仕様だけを書く

> 対象はすべてのプラットフォームの本番コードとテストコードです。フレームワーク固有の記法（doc comment の形式）は各フレームワークの coding 末端ファイルが上書きし、この文書は書く内容と書かない内容だけを定めます。新しいフレームワークを追加したら、その言語の拡張子を上記 `applyTo:` に追加します。コメントは利用プロジェクトの `harness.config.json` の `policy.language`（未宣言なら日本語）で書き、識別子、API 名、フレームワークのキーワードは維持します。

## 到達状態

コメントは、今このコードを読む人が**現在の仕様**を理解するためだけに存在します。履歴は git コミットメッセージと ADR にあり、コードに複製すると更新されない 2 つ目の記録になります。

- **書かないもの（見つけたら触った範囲で削除する）**: 過去との差分（「以前は X だったが Y に変更した」）、作業記録や日付・担当者・チケット番号だけの注記、コメントアウトした古いコード、変更の意図（コミットメッセージ / ADR へ）、コードの言い換え。
- **書いてよいもの**: 読むだけでは分からない理由と制約（外部仕様の癖、意図的に非効率な選択、回避しているバグ）、壊れやすい前提と不変条件、フレームワークが要求する doc comment。すべて現在形で書きます。
- 履歴コメントが現在の仕様の説明も兼ねていたら、先に現在形へ書き直してから履歴部分を落とします。正しいか確認できないコメントはコードを正として判断し、コメントを根拠に実装を変えません。清掃は同じコミットの一部として扱い、報告に 1 行残します。

## トレーサビリティ注釈（ID のみ）

`trace-check`（`"${HARNESS_ROOT}/tools/trace-check/"`）が読む、必ず入れる唯一のコメントです。**書くのはテストコードだけ**です（ADR-0070）。要件を言い換えず ID だけを書きます（存在しない・撤回済みの ID は C3 / C15 / C20）。注釈は**コメントの中**に書きます（文字列リテラルの中の注釈は数えません）。テストへの注釈は、テストの行か、その直上に連続するコメント行（空行・コード行で切れる）に書きます（`after` を宣言した場合はテストの行か次の行）。行頭が `#` / `@` の行の注釈は、その前に `//` などのコメント開始記号があるか、`harness.config.json` の `comment_pattern` がその言語の `#` をコメントと宣言した場合だけ数えます。

- **本番コードとスキーマ正本**: 紐づきの印（`@implements`・`@operation` など、仕様の ID を指すだけのコメント）を書きません。機械は読まないので、書いても検査されず、要件を撤回しても残ります。見つけたら、触った範囲で削除します。実装と仕様の対応は、実行して確かめます: どのテストからも実行されないファイルと関数は `harness lint coverage`、契約に無い入口は `harness lint entries` が検出します。
- **テストコード**: テストごとに `@covers REQ-nnn#class` を宣言済みクラスにちょうど 1 つ（2 つ以上は C11）。位置は利用プロジェクトが `harness.config.json` の `tests.covers_placement` に宣言し、C10 / C11 が検査します。シナリオテストは同じ位置に `@scenario UC-nnn`（C15）。NFR を検証するテストは同じ位置に `@covers NFR-nnn`（クラスなし、REQ の `@covers` とは別に数える。C20）。保留のテスト（`pending_pattern` に一致）は被覆に数えません。テストの行以外にある保留の印（`describe.skip` など）はそのファイルの全テストを保留にします。
- **規則を確かめるテスト**: 規則（BR）を直接確かめるテストは、同じ位置に `@covers BR-nnn`（クラスなし、REQ の `@covers` とは別に数える）。`enforced_at` が DB の BR には、このテストが必ず要ります（C13）。アプリの入口を通さず、規則に反する行を DB に直接入れて、断られることを確かめます（入口を通すと、手前の検証と DB の制約のどちらが断ったのかを区別できません）。シナリオテストには書きません。
- **仕様を持たないテスト**（技術部品の自己検査）は `tests.dirs` の外に置きます。`tests.dirs` のテストに `@covers` が無ければ C11 が検出します（ADR-0055）。
- 注釈は現在の仕様の参照先です。要件の撤回や移動と同じ変更で更新・削除します。
