# Righthub — ファイル保存

ファイル保存を使う機能だけに適用する。認可は[セキュリティ](backend-security.instructions.md)に従う。

- 非公開ファイルは静的配信の document root とリリースディレクトリの外に置き、専用ユーザーに必要な権限だけを与える。
- 認可済み API 経由でアップロード / ダウンロードする。主体、テナント、リソース、読み書きを認可し、不透明なキーだけでアクセスを許可しない。
- 保存キーはサーバーが生成する。利用者指定の名前をパスとして連結せず、パストラバーサルとシンボリックリンクによる保存領域外の読み書きを防ぐ。
- サイズ、コンテンツ型、頻度、ディスク容量に上限を設け、ストリーム処理と中断時の一時ファイル削除を行う。拡張子や申告 MIME だけで内容を信頼しない。
- 検証後に同一ファイルシステム内の atomic rename 等で確定し、所有、存在、サイズを確認してメタデータを公開する。DB 更新とは別の原子性なので、冪等な確定、失敗後の修復、放棄ファイルの削除を定義する。
- ダウンロードは意図した content type、disposition、キャッシュヘッダーで配信し、利用者コンテンツをアプリのオリジンで実行させない。内部転送で配信を委ねる場合も、公開 URL から認可を迂回できないようにする。
- 保存領域と DB の整合したバックアップ、復元、保持と削除方針を宣言する。コンテナの書き込み層や一時ディレクトリを永続保存先にしない。
