# 🚦 SwiftUI — テスト実行の進め方（シミュレーターは共有資源）

既定スイートの実行にシミュレーターの destination が必要な構成（アプリターゲットの `xcodebuild test`）と、[システムスイート](system-testing.instructions.md)（XCUITest）に適用する。既定スイートが `swift test` だけで完結するなら排他は生じず、この文書は適用しない。判断できなければホストの `CLAUDE.md` の既定スイート実行コマンドで判断する。誰が、いつ実行するかだけを持つ。報告は日本語。

## 不変条件

- シミュレーター、DerivedData、ビルドロックは単一の共有資源。`xcodebuild` を同時に 2 プロセス動かさない（parallel-test-execution による多重プロセスも含む）。
- destination は 1 つに固定し、ホストの `CLAUDE.md` に宣言したデバイス名と OS バージョンを毎回使う。起動済みシミュレーターを再利用し、実行ごとに作成・削除・再起動しない。
- 誰も実行していないものを次のフェーズへ渡さない。Red / Green は実行したコマンドの終了コードで判断する。

## 並行区間

- 並行実行中の producer はテストを実行しない（`xcodebuild test`、テスト目的の `simctl boot`）。編集、型チェック、lint、シミュレーター不要のビルドまでで止める。
- 省略したら、テストが未実行であることと、実行が必要なスイート（対象 UC ID）を報告に明記する。
- 例外は 2 つだけ: 作成直後の Red 確認（新規テストだけの選択実行。他の Task の実行は観測できないので、判断できなければ実行する）と、人間ゲートのための外観確認のシミュレーター起動。

## 集約実行

- 並行区間が閉じたら、単独で動く 1 agent がまとめて実行し、そこで Red / Green を確定する。
- 修正ラウンドでは選択実行（報告に挙げた UC スイートと影響範囲の近隣 `UC-nnn` に `-only-testing:` またはホストの `CLAUDE.md` の相当手段）、既定スイート全体は完了条件と CI だけ。ループ中の「Green」は選択した範囲が Green という意味。
