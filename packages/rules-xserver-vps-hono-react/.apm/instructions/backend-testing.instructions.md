# Hono / Node.js — バックエンドテスト

入口、スイート分離、注釈は[共通テスト](common-testing.instructions.md)に従う。ブラウザシナリオには適用しない。

## 既定スイート

| 対象 | テスト境界 |
| --- | --- |
| 純粋な業務関数 | モックなしで同値分割を検証 |
| service | repository のポートを注入し、シナリオの結果を検証 |
| Hono の入口 | 宣言済み route factory を `Request` で実行し、基盤は境界でフェイク |
| メッセージ処理 | 宣言済みポートへフレームを渡し、永続化 / 配送をフェイク |

- 動作は固定契約と REQ の分割クラスから導出する。実装が偶然 export した入口を import しない。
- 検証エラー、認証 / 認可の拒否、成功時の呼び出し、結果から公開ステータス / body への変換を確認する。契約が要求する Origin / CSRF、upgrade 拒否、失効、冪等性も検証する。
- 純粋関数をモックせず、認可は制御した境界データで実際の方針を実行する。常に許可するフェイクで認可欠落を隠さない。
- 実 DB、実ネットワーク、ブラウザは既定スイートで起動しない。

## ランタイム統合

- 本番と同じ Node.js / PostgreSQL の版で実行し、DB と保存ディレクトリを実行ごとに分離する。SQLite 等で PostgreSQL の制約・トランザクションを代替しない。fixture を明示的に投入し、本番リソースに接続しない。
- 実際のマイグレーションを適用し、制約、条件付き更新、トランザクションのロールバック、同時更新、方言依存 SQL を検証する。
- WebSocket は実通信、再起動後の復旧、重複排除、再開時の欠落と並行性を検証する。生きたプロセスの再利用だけで再起動を網羅したと主張しない。
- ファイル保存は認可、領域外へのアクセス拒否、検証 / 確定、容量不足、中断、欠落、再試行 / 削除を確認する。
- 本番相当のプロキシとビルド成果物で API / SPA の振り分けを検証する。API 失敗を HTML 成功にしない。プロトコル確認をブラウザスイートへ入れない。
- ローカル成功は VPS の容量、ファイアウォール、TLS 更新、バックアップ復元を証明しない。検証した構成と未検証の運用項目を区別する。
